1. Run it

npm run setup          # installs server + client packages
cp server/.env.example server/.env   # set MySQL user/password, JWT secret, super admin login
npm run migrate        # creates the MySQL tables (server/src/schema.sql)
npm run seed           # creates the super admin   (or: npm run demo  -> also demo farm "XYZ Polyhouse")
npm run dev            # API on :4000 + React on :5173 (open http://localhost:5173)
npm run build && npm start   # production: Express serves the built React app on :4000
Demo logins (after npm run demo): super admin superadmin / admin123, owner xyz / xyz123, supervisor super1, delivery delivery1, vendor vendor1, labour labour1 (password demo123).

7. Business rules in one place

  • Sale amount = (quantity − rejected) × rate. Rate = vendor price list (latest effective date) → else crop default price. Delivery/supervisor cannot change the rate.
  • Vendor can confirm or report rejected quantity within 7 days; amount is recalculated, status becomes accepted / disputed.
  • Overdue = vendor balance minus sales still inside the vendor's credit days.
  • Spray with PHI days locks harvest of that bay (or the whole farm if no bay) until date + PHI. Owner can override.
  • Purchase expense with a stock item → stock in. Stock out is entered in Stock in/out.
  • Expense paid by "credit" (or part-paid) → payable to supplier in the balance sheet.
  • Recurring payments with auto-post are added to Expenses when due (checked on dashboard load).
  • Wages: daily = days × wage; monthly = salary/30 × period days − absent days; piece = kg × rate; overtime = hours × day wage / 8. Paying posts gross + bonus as a Labour expense and recovers advances.
  • Cost per crop = direct expenses tagged to its crop cycle + share of all other costs (incl. depreciation) by area × days of running crop cycles.
  • Balance-sheet cash = opening cash (Settings) + money in − money out from the books-start date.
  • Turning a module off hides its screens and blocks its API; data is kept.
